# GitHub Actions CI for slideio-python — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give this repository a per-commit build gate on push and pull request, and a tag-driven release that checks the tag against `projectVersion` and attaches every platform's wheels to a draft GitHub Release.

**Architecture:** Two new workflows. `build-validation.yml` builds the C++ library, one Python 3.12 wheel and runs `tests/` on manylinux, macOS arm64 and Windows. `release.yml` derives the version from the tag, then calls the three existing wheel workflows — which gain `on: workflow_call` so nothing is duplicated — and publishes a draft Release. The only non-YAML logic, deriving the version from the tag, moves into `ci_version.py` so it can be unit-tested; everything else is pinned by structural tests that read the workflow YAML.

**Tech Stack:** GitHub Actions, PyYAML (new dev dependency), `unittest` run under pytest, `softprops/action-gh-release@v2`, `actions/{checkout,cache,setup-python,upload-artifact,download-artifact}@v4-v5`.

**Spec:** `docs/superpowers/specs/2026-10-01-python-ci-design.md`

## Review Focus

Five things the spec implies, that no task's primary assertions would otherwise exercise. Each has a test attached to the task that owns the code.

1. **A tag with a leading-zero patch (`v2.10.03`).** PEP 440 normalises `2.10.03` to `2.10.3`, so every wheel filename would disagree with the tag that produced it. Must be rejected, not accepted. → Task 1.
2. **YAML resolves the bare key `on:` to the boolean `True`.** PyYAML hands back `{True: {...}}`, so `workflow['on']` raises `KeyError` — and a structural test written the obvious way either errors or, worse, passes vacuously. → Task 2 (`triggers()` helper plus a test that it returns something for every file).
3. **A called workflow receiving no patch.** A manual dispatch passes no `ci_pipeline_iid`; the version must come out `X.Y.0`, never `X.Y.` or `X.Y.None`. → Task 2.
4. **Two artifact uploads with no `name:`.** `macos-wheels.yml:102` and `windows-wheels.yml:90` both default to `artifact` today, which collides under `upload-artifact@v4` the first time one run uploads both. → Task 2.
5. **pytest run from inside the checkout.** `import slideio` then resolves to the source tree beside it and the run silently tests whatever the last local build left behind, not the wheel. → Task 2 and Task 3.

```python
#!/usr/bin/env python3
"""Derive the package version for a release from CMakeLists.txt and the git ref.

CMakeLists.txt carries MAJOR.MINOR (`set(projectVersion 2.10)`); the patch
component comes from the tag being released. setup.py:38-41 reads that patch
from CI_PIPELINE_IID, so release.yml exports what this script reports and the
tag becomes the single source of the patch number -- cutting a patch release
needs no file edit.

    python ci_version.py                                    # no tag: patch 0
    GITHUB_REF_TYPE=tag GITHUB_REF_NAME=v2.10.3 python ci_version.py

Prints `version=<v>` and `patch=<p>`, and appends both to $GITHUB_OUTPUT when
that variable is set. Exits 1 with the reason on stderr when the tag and
CMakeLists.txt disagree -- before any platform starts building wheels whose
names would be wrong.
"""
import os
import re
import sys

HERE = os.path.dirname(os.path.abspath(__file__))
CMAKELISTS = os.path.join(HERE, 'CMakeLists.txt')

# No leading zeros in any component: pip normalises 2.10.03 to 2.10.3 (PEP 440),
# which would leave every wheel in the release named differently from its tag.
TAG = re.compile(r'^v(0|[1-9]\d*)\.(0|[1-9]\d*)\.(0|[1-9]\d*)$')

# The same setting setup.py:30 reads, and tolerant of trailing arguments because
# CLAUDE.md documents the form as `set(projectVersion MAJOR.MINOR ...)`.
PROJECT_VERSION = re.compile(r'set\s*\(\s*projectVersion\s+(\d+\.\d+)')


def read_project_version(path=CMAKELISTS):
    """Return MAJOR.MINOR from `set(projectVersion ...)`, or None if absent."""
    with open(path, encoding='utf-8') as handle:
        for line in handle:
            match = PROJECT_VERSION.search(line)
            if match:
                return match.group(1)
    return None


def derive(project_version, ref_type, ref_name):
    """Return (version, patch). Raise ValueError with the reason if they clash."""
    if project_version is None:
        raise ValueError(
            'Could not read projectVersion from CMakeLists.txt.')
    if ref_type != 'tag':
        return '{}.0'.format(project_version), '0'
    match = TAG.match(ref_name)
    if not match:
        raise ValueError(
            'Tag {} is not of the form vMAJOR.MINOR.PATCH with no leading '
            'zeros.'.format(ref_name))
    major, minor, patch = match.groups()
    if '{}.{}'.format(major, minor) != project_version:
        raise ValueError(
            'Tag {} does not match projectVersion {} in CMakeLists.txt. '
            'Update projectVersion or retag.'.format(ref_name, project_version))
    return '{}.{}.{}'.format(major, minor, patch), patch


def main():
    try:
        version, patch = derive(read_project_version(),
                                os.environ.get('GITHUB_REF_TYPE', ''),
                                os.environ.get('GITHUB_REF_NAME', ''))
    except ValueError as error:
        print(error, file=sys.stderr)
        return 1
    print('version={}'.format(version))
    print('patch={}'.format(patch))
    output = os.environ.get('GITHUB_OUTPUT')
    if output:
        with open(output, 'a', encoding='utf-8') as handle:
            handle.write('version={}\n'.format(version))
            handle.write('patch={}\n'.format(patch))
    return 0


if __name__ == '__main__':
    sys.exit(main())
```

```python
"""Structural tests for the GitHub Actions workflows.

These cover CI configuration rather than the built wheel, so they read the YAML
from the repository root instead of importing the installed package -- the same
arrangement tests/test_msvcredist.py uses for build tooling. The suite is run
from outside the checkout (see CLAUDE.md), so paths are derived from this file's
own location. It needs neither a built wheel nor SLIDEIO_IMAGES_PATH.

Each assertion stands for a failure that is otherwise invisible until a release:
an unnamed artifact that collides with another platform's, a cache key that has
silently stopped tracking the submodule commit, a publish job a manual run could
reach, a test step that runs pytest from inside the checkout and so imports the
source tree instead of the wheel.
"""
import os
import unittest

import yaml

WORKFLOW_DIR = os.path.join(
    os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
    '.github', 'workflows')

WHEEL_WORKFLOWS = ('linux-wheels.yml', 'macos-wheels.yml',
                   'windows-wheels.yml')
ALL_WORKFLOWS = WHEEL_WORKFLOWS + ('build-validation.yml', 'release.yml')


def read(name):
    with open(os.path.join(WORKFLOW_DIR, name), encoding='utf-8') as handle:
        return handle.read()


def load(name):
    return yaml.safe_load(read(name))


def triggers(workflow):
    """Return the `on:` block.

    YAML 1.1 resolves the bare key `on` to the boolean True, which is what
    PyYAML hands back -- so `workflow['on']` raises KeyError for a reason that
    has nothing to do with CI. Both spellings are accepted here because a
    quoted `"on":` in a future edit would parse as the string.
    """
    if 'on' in workflow:
        return workflow['on']
    return workflow[True]


def steps_of(workflow):
    """Yield (job_name, step) for every job that defines steps.

    Jobs that only `uses:` a reusable workflow have no steps and are skipped.
    """
    for job_name, job in workflow.get('jobs', {}).items():
        for step in job.get('steps') or []:
            yield job_name, step


class TestEveryWorkflow(unittest.TestCase):
    def test_all_parse(self):
        for name in ALL_WORKFLOWS:
            with self.subTest(workflow=name):
                self.assertIsInstance(load(name), dict)

    def test_triggers_are_reachable(self):
        # Without this, the `on:`/True trap above could make every other
        # trigger assertion in this file pass vacuously.
        for name in ALL_WORKFLOWS:
            with self.subTest(workflow=name):
                self.assertTrue(triggers(load(name)))

    def test_no_dead_environment_variables(self):
        # SLIDEIO_HOME is read by nothing in this repository, the pinned
        # extern/slideio, or the C++ working copy; CONAN_DISABLE_CHECK_COMPILER
        # is a CMake variable (CMakeLists.txt:48), not an environment one; and
        # CONAN_REVISIONS_ENABLED is a Conan 1 knob in a Conan 2 build.
        for name in ALL_WORKFLOWS:
            for dead in ('SLIDEIO_HOME', 'CONAN_REVISIONS_ENABLED',
                         'CONAN_DISABLE_CHECK_COMPILER'):
                with self.subTest(workflow=name, variable=dead):
                    self.assertNotIn(dead, read(name))

    def test_skip_missing_images_is_never_set(self):
        # CLAUDE.md: CI must leave it unset, so a missing image fails the run
        # instead of quietly skipping the test that needed it.
        for name in ALL_WORKFLOWS:
            with self.subTest(workflow=name):
                self.assertNotIn('SLIDEIO_SKIP_MISSING_IMAGES', read(name))

    def test_cache_keys_do_not_hash_the_git_directory(self):
        # hashFiles() on a glob that matches nothing returns an empty string,
        # restore-keys then papers over the degraded key, and the cache stops
        # tracking the submodule commit with nothing in the log to say so.
        for name in ALL_WORKFLOWS:
            with self.subTest(workflow=name):
                self.assertNotIn('.git/modules', read(name))

    def test_uploads_are_named_and_fail_when_empty(self):
        for name in ALL_WORKFLOWS:
            for job, step in steps_of(load(name)):
                if not str(step.get('uses', '')).startswith(
                        'actions/upload-artifact'):
                    continue
                with self.subTest(workflow=name, job=job):
                    parameters = step.get('with', {})
                    self.assertIn('name', parameters)
                    self.assertEqual('error',
                                     parameters.get('if-no-files-found'))

    def test_pytest_always_runs_from_outside_the_checkout(self):
        # The repository root holds a slideio/ package directory, so pytest run
        # from inside the checkout imports the source tree rather than the
        # installed wheel (CLAUDE.md).
        found = 0
        for name in ALL_WORKFLOWS:
            for job, step in steps_of(load(name)):
                run = str(step.get('run', ''))
                if 'pytest' not in run:
                    continue
                found += 1
                with self.subTest(workflow=name, job=job):
                    self.assertTrue(
                        'cd "$RUNNER_TEMP"' in run
                        or 'Set-Location $env:RUNNER_TEMP' in run,
                        'this pytest step never leaves the checkout')
        self.assertGreater(found, 0, 'no pytest step found at all')


class TestWheelWorkflows(unittest.TestCase):
    def test_callable_and_dispatchable(self):
        for name in WHEEL_WORKFLOWS:
            with self.subTest(workflow=name):
                on = triggers(load(name))
                self.assertIn('workflow_call', on)
                self.assertIn('workflow_dispatch', on)

    def test_orchestration_inputs_are_declared(self):
        for name in WHEEL_WORKFLOWS:
            with self.subTest(workflow=name):
                inputs = triggers(load(name))['workflow_call']['inputs']
                self.assertEqual('string', inputs['ci_pipeline_iid']['type'])
                self.assertEqual('string', inputs['artifact_name']['type'])

    def test_patch_defaults_to_zero_not_empty(self):
        # A manual dispatch passes no patch. setup.py:40 treats '' as absent and
        # falls back to '0', so '' would work -- but '0' says what the version
        # will be instead of depending on that fallback.
        for name in WHEEL_WORKFLOWS:
            with self.subTest(workflow=name):
                inputs = triggers(load(name))['workflow_call']['inputs']
                self.assertEqual('0', inputs['ci_pipeline_iid']['default'])

    def test_patch_reaches_the_build_environment(self):
        for name in WHEEL_WORKFLOWS:
            with self.subTest(workflow=name):
                self.assertIn('CI_PIPELINE_IID: ${{ inputs.ci_pipeline_iid }}',
                              read(name))

    def test_default_artifact_names_are_distinct(self):
        defaults = [
            triggers(load(name))['workflow_call']['inputs']
            ['artifact_name']['default'] for name in WHEEL_WORKFLOWS]
        self.assertEqual(len(defaults), len(set(defaults)))
        for default in defaults:
            # release.yml's publish job downloads with pattern wheels-*.
            self.assertTrue(default.startswith('wheels-'), default)

    def test_uploads_use_the_artifact_name_input(self):
        for name in WHEEL_WORKFLOWS:
```

```yaml
name: Release

# Builds every platform's wheels for a version tag and attaches them to a draft
# GitHub Release:
#
#   wheels-manylinux_2_28-x86_64   CPython 3.9-3.14, glibc 2.28 floor
#   wheels-macos-arm64             CPython 3.9-3.14
#   wheels-macos-x86_64            CPython 3.9-3.13
#   wheels-windows-x86_64          CPython 3.9-3.14
#
# The wheels themselves are built by the three per-platform workflows, which
# this one calls rather than copies -- each platform's quirks stay in one place.
# build-validation.yml remains the per-commit gate and is untouched.
#
# PyPI upload is still manual; nothing here talks to an index.

on:
  push:
    tags:
      - 'v*'
  workflow_dispatch:
    inputs:
      platforms:
        description: 'Which platforms to build'
        required: true
        default: 'all'
        type: choice
        options:
          - all
          - windows
          - macos
          - manylinux

# A manual run cannot publish: the publish job is gated on the event being a tag
# push, and a tag push never carries inputs. So the knob above only ever
# shortens a rehearsal, and it cannot put an untested artifact on a release page
# -- not even a manual run started against a tag ref, which the dispatch API
# accepts as readily as a branch.
#
# Note that GitHub offers the "Run workflow" button only for workflow files that
# exist on the default branch. Until this file is merged to main it cannot be
# dispatched from anywhere, including from its own branch.

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  # Unlike the gate: a half-cancelled release is worse than two of them.
  cancel-in-progress: false

jobs:
  # A tag is the only thing that says which version is being released, and
  # CMakeLists.txt is the only thing that says which MAJOR.MINOR is being built.
  # They have to agree before four platforms spend an hour producing wheels
  # whose names would otherwise be wrong. ci_version.py owns the rules and is
  # unit-tested in tests/test_ci_version.py.
  check-version:
    name: Check version
    runs-on: ubuntu-latest
    outputs:
      version: ${{ steps.version.outputs.version }}
      patch: ${{ steps.version.outputs.patch }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: '3.x'

      - name: derive the package version from the tag
        id: version
        run: python ci_version.py

  wheels-manylinux:
    name: manylinux_2_28 x86_64
    needs: check-version
    # A dispatch can ask for one platform; a tag push carries no inputs and so
    # builds everything.
    if: contains(fromJson('["all","manylinux"]'), inputs.platforms || 'all')
    uses: ./.github/workflows/linux-wheels.yml
    with:
      ci_pipeline_iid: ${{ needs.check-version.outputs.patch }}
      artifact_name: wheels-manylinux_2_28-x86_64

  wheels-macos-arm64:
    name: macOS arm64
    needs: check-version
    if: contains(fromJson('["all","macos"]'), inputs.platforms || 'all')
    uses: ./.github/workflows/macos-wheels.yml
    with:
      os: macos-14
      ci_pipeline_iid: ${{ needs.check-version.outputs.patch }}
      artifact_name: wheels-macos-arm64

  wheels-macos-x86_64:
    name: macOS x86_64
    needs: check-version
    if: contains(fromJson('["all","macos"]'), inputs.platforms || 'all')
    uses: ./.github/workflows/macos-wheels.yml
    with:
      os: macos-15-intel
      ci_pipeline_iid: ${{ needs.check-version.outputs.patch }}
      artifact_name: wheels-macos-x86_64

  wheels-windows:
    name: Windows x86_64
    needs: check-version
    if: contains(fromJson('["all","windows"]'), inputs.platforms || 'all')
    uses: ./.github/workflows/windows-wheels.yml
    with:
      ci_pipeline_iid: ${{ needs.check-version.outputs.patch }}
      artifact_name: wheels-windows-x86_64

  publish:
    name: Publish release
    needs:
      - check-version
      - wheels-manylinux
      - wheels-macos-arm64
      - wheels-macos-x86_64
      - wheels-windows
    # Only a tag *push* publishes. A manual run stops after the wheels, having
    # produced and tested every artifact -- which is what makes it a usable
    # rehearsal.
    #
    # Both halves of this condition are load-bearing. github.ref_type alone is
    # not enough: the dispatch API takes a tag as readily as a branch, so a
    # manual run started against v2.10.3 also reports ref_type == 'tag'. It
    # would reach this job carrying whatever the inputs asked for and publish a
    # release built from one platform. Requiring event_name == 'push' is what
    # makes "a manual run cannot publish" true rather than merely usually true.
    if: github.event_name == 'push' && github.ref_type == 'tag'
    runs-on: ubuntu-latest
    permissions:
      contents: write

    steps:
      - name: download every platform's wheels
        uses: actions/download-artifact@v4
        with:
          pattern: wheels-*
          path: dist
          merge-multiple: true

      - name: list what will be published
        run: ls -la dist

      - name: create the GitHub Release
        uses: softprops/action-gh-release@v2
        with:
          files: dist/*
          name: slideio ${{ needs.check-version.outputs.version }}
          draft: true
          generate_release_notes: true
          fail_on_unmatched_files: true
          body: |
            Python wheels for slideio ${{ needs.check-version.outputs.version }}.

            | Platform | Wheels |
            |---|---|
            | Linux x86_64 (manylinux_2_28) | CPython 3.9–3.14 |
            | macOS arm64 | CPython 3.9–3.14 |
            | macOS x86_64 | CPython 3.9–3.13 |
            | Windows x86_64 | CPython 3.9–3.14 |

            Install a downloaded file directly:

            ```
            pip install ./slideio-${{ needs.check-version.outputs.version }}-cp312-cp312-*.whl
            ```

            The PyPI upload for this version is made separately.
```

```markdown
### CI

Two workflows, mirroring the C++ repository's split.

`build-validation.yml` is the per-commit gate: push and pull request against
`main`, plus manual dispatch, with `cancel-in-progress` so a new push supersedes
the old run. Three independent jobs — manylinux in the pinned container, macOS
```
